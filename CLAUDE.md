## Build and gates (in `NuvioMobile/`)
- Kotlin: `./gradlew :shared:jvmTest :shared:tvosSimulatorArm64Test :composeApp:iosSimulatorArm64Test`
- Sim builds (Debug + Release): `xcodebuild -project iosApp/iosApp.xcodeproj -scheme NuvioTV -configuration Release -destination 'platform=tvOS Simulator,id=FA87E9B6-F28D-4DF9-84E4-A5A4C5DBFC4E' -derivedDataPath iosApp/build/DerivedData` (the FA87 id, never `generic/platform=tvOS Simulator`: Release has no `ONLY_ACTIVE_ARCH`, so the generic destination links x86_64 against the arm64-only SharedCore and fails; 2026-10-22).
- NuvioTVTests + UI legs on the fixture sim (`FA87E9B6-…`): `xcodebuild test -scheme NuvioTVTests` (unit) / `-scheme NuvioTVUITests -only-testing:NuvioTVUITests/<Class>` (legs) `… -derivedDataPath iosApp/build/DerivedDataUITests -collect-test-diagnostics never` (the `NuvioTV` scheme has no testables: "not configured for the test action"), Bash sandbox OFF (sandboxed: exit 70 "Failed to prevent system sleep"; without the flag UI legs hang ~10 min). Iteration runs of UI legs go on the project's own sim clone (`scripts/device/sim.sh clone <project>` prints the `-destination`, 2026-11-09); FA87 is the final gate, under `scripts/build/with-sim-lock.sh`.
- Device build: `-destination 'platform=tvOS,id=00008110-001A6DCE0AF2201E' -derivedDataPath iosApp/build/DerivedDataDevice -allowProvisioningUpdates -allowProvisioningDeviceRegistration 'PRODUCT_BUNDLE_IDENTIFIER=$(PRODUCT_BUNDLE_IDENTIFIER_$(TARGET_NAME):default=$(inherited))' PRODUCT_BUNDLE_IDENTIFIER_NuvioTV=com.youngchris29.NuvioTV PRODUCT_BUNDLE_IDENTIFIER_NuvioTopShelf=com.youngchris29.NuvioTV.NuvioTopShelf` — the concrete Living Room destination plus `-allowProvisioningDeviceRegistration` is required: the free team's device list was empty and `generic/platform=tvOS` fails with "Your team has no devices from which to generate a provisioning profile" (xcodebuild registers the box itself with the flag). The override is mandatory: the free team cannot sign `com.nuvio.media.NuvioTV`, and without it the build installs as a second app while the rig launches the old one (2026-10-27). 7-day free-team profile; delete stale `youngchris29` profiles when it expires. Install with `devicectl device install app`, launch via `scripts/device/console.sh` or `atv.sh launch`.
- Gated = all of the above green on the tip plus the relevant UI legs, then a device pass in the Test profile.
- Keep only those three dirs plus `tvos-ipa` under `iosApp/build/`; delete one-off build dirs and `.xcresult` bundles once their gate is recorded.

## Release chain
1. Feature branch in a local clone of the submodule (never a worktree); review loop to CLEAN; gates green.
2. Fast-forward into `tvos-shared-extraction`, push, delete the branch (local + `origin`) and the clone.
3. Bump the outer pointer: `git add NuvioMobile`, commit, push outer `main`.
4. Cut only on Christian's explicit go: `scripts/cut-rc.sh beta.<n>-rc<m>` (preflight, build bump + tag, push, pointer commit, Release build, package, upload; `--preflight` checks only, `--from build|upload` resumes). Public betas: `NuvioMobile/scripts/release-beta.sh`.
5. Tester DM through the copy rule, sent only on his go.

## Branch hygiene
- Outer `origin` carries `main` only. Cloud sweeps never commit or branch; delete any `claude/*` branch once it is an ancestor of `main`.
- Submodule `origin` holds `tvos-shared-extraction` and `cmp-rewrite` (stale mirror). Fork tags are `tvos-*`; never push upstream's `0.x` tags.
- Never `git worktree add`/`remove` on the submodule (`core.worktree` resolves back to `.git/modules/NuvioMobile`); a stray one is removed with `rm -rf` + `git worktree prune`. Isolated work goes in a clone `~/Claude/Projects/NuvioMobile-<task>`, landed with `git fetch <clone> <branch>:<branch>`; in a clone MPVKit is a symlink over the gitlink, so stage by explicit paths, never `git add -A`.
- Delete a side clone once its branch is fast-forwarded in. `~/Claude/Projects/NuvioMobile-ios-sideload` is not one of these: it is the standing upstream checkout for the iPad sideload (see below), detached at a release tag, never committed or pushed.
- Commit the `docs/*.md` the checks and sweeps write.

## Knowledge graph (graphify, standing, 2026-10-26)
`NuvioMobile/graphify-out/` (gitignored; tree-sitter code graph of the submodule, no LLM, `graphify` CLI via uv) is the first stop for any codebase question, run from the submodule: `cd NuvioMobile && graphify query "<question>"` / `explain "<symbol>"` / `path "<A>" "<B>"` / `affected "<symbol>"` (those forms are pre-allowed in `.claude/settings.json`). The PreToolUse hook there nudges toward the graph before Bash/Grep/Read/Glob and carries `GRAPHIFY_OUT=NuvioMobile/graphify-out` inline because it runs at this root; never export that variable in a shell, it breaks graphify inside `NuvioMobile/`. Same-named Swift/Kotlin symbols are refused as ambiguous: pass `<file path>::Symbol`.
- Freshness: local git hooks in the submodule (post-commit/checkout/merge/rewrite) rebuild the graph; after a fast-forward from a clone or `git pull`, run `graphify update .` in `NuvioMobile/` (free). Never `/graphify .` on this outer folder: the semantic pass over `docs/` is a paid subagent fan-out; point it at a curated subset if ever.
- Upstream port triage: before dismissing a `cmp-rewrite` hunk in `shared/`, `graphify explain "<symbol>"` lists every `composeApp`/`appleMain`/`NuvioTV` consumer (the grep-before-dismissing rule, now one call).

No scorer tricks; legal/DMCA and quoted third-party text are never rewritten.

## Long-running work (standing, 2026-11-09)
From the Add-ons hub, Detail Polish and Stream Picker #25 retrospectives. Applies to every multi-wave batch, cloud or Mac.
- **Plan approval carries the standing go.** Waves run back to back while green; stop only on a failed gate, a blocker or a design question. Cut, tag, post, DM and the Chris profile still wait for Christian's word. An approval that says "land when green" is the push go for that batch's fast-forward of `tvos-shared-extraction` and the outer pointer (branch and clone deleted after); it covers nothing else.
- **Reversible choices proceed on the recommendation.** A card about a choice that can still be changed before a cut (UI sizes, line caps, defaults on unreleased work) proceeds with the recommended option after 30 minutes with no answer, says so on the card, and is listed in the batch doc for override.
- **Review cap.** P1/P2 findings are always fixed. After round 6 on a wave, two consecutive rounds confined to one narrow area, or a diff grown more than 50%, stop and bring Christian a card (best-effort vs keep going, with a one-line summary of the last rounds). Specs mark each protection "invariant" (review to CLEAN) or "best-effort" (decline and log edge cases). A finding is declined as Christian's call only if it disputes what he decided; a consequence he was never shown is fixed or brought to him. Budget Codex per stage: Codex for the first and the whole-stage round, the Opus stand-in for delta rounds when quota is low.
- **Heartbeat.** Every reply ends with "Waiting on you: … / Running: …". The working session posts a line after compile, each review round, UI legs, the device pass and landing, and at least every 30 minutes while waiting, naming what it waits on and for how long. The coordinator answers status questions from that checklist, never by relaying.
- **One lettered decision doc per batch.** The plan lists every foreseeable decision with a recommendation; later questions from every thread are added to the same list, and Christian answers once per sitting. Gos belong in the work thread that pushes, not the project chat.
- **Processes.** Kill only PIDs you started (keep them in a pid file); never pattern-kill `xcodebuild`/`xctest`/`simctl`/`gradle`/`codex`; never shut down or reboot a sim you didn't boot. Each session uses its own sim clone (`scripts/device/sim.sh clone <project>`, cloned from the shut-down "NuvioTV template") and its own DerivedData; FA87 is for the final gate only, wrapped in `scripts/build/with-sim-lock.sh`; builds wrap `scripts/build/with-lock.sh`.
- **Box ownership.** `scripts/device/ready.sh --project <batch-or-clone-name> [--eta <text>]` takes the box lock (`scripts/device/lock.sh`; exit 3 BUSY = say so once and `lock.sh wait box <project> --timeout 1800`, never kill the holder); `atv.sh` and `console.sh` refuse while another project holds it. `ready.sh --walk` launches the app with its console instead of stopping on "app not running" and takes a `pre` settings snapshot. End every pass with `scripts/device/done.sh <project>`: settings diff against the snapshot (restore anything the pass flipped in Test 2), Home, lock release. `ready.sh` also starts `keep-awake.sh` for 4 h. Details: `docs/device-rig-2026-10-15.md`, 2026-11-09 section.
- **Draft PRs stay unmerged until gated.** A cloud PR merges only after its Mac round is green; the plan sets the landing order, and each later round builds on the branch before it. Hot files (`StreamsRepository.kt`, `StreamModels.kt`, `DetailCinematicHero.swift`, `Localizable.xcstrings`) get one owning thread per batch; a thread that adds a shared helper tells the coordinator.
- **Landing preflight** before any "land" go is acted on: base unchanged (else rebase, delta review and gates first), Remote Control sign-in fresh, Xcode signed in, box free, free-team profile over 2 days left, review quota available. Any failure is one message before the work starts.
- **Plan from an inventory.** Before writing a stage, `graphify query` for features that already exist in its area. A size change names the screen it must fit and the real measurement it was checked against (the pane in the 1080p sim, not the nominal screen) and gets a geometry assertion; UI tests of layout measure the laid-out view, never accessibility frames. The plan's first task confirms every input is readable from where the work runs (cloud sessions cannot see Mac-only files).
- **Human checks are scheduled.** VoiceOver, phone passes and design picks get a wave in the plan, not the end. Each batch doc carries the Decisions, Waves and review rounds, Not verified and By hand tables from `docs/obsidian/templates/batch.md`; the cut preflight reads Not verified; the by-hand list is cleared in one sitting before each cut.
- **Cut decision at the end of each batch:** cut now, combine with the next batch, or hold. For a screen redesigned in the last two weeks, offer to post the mockup to the requester before building (outward post, needs the go).
- **Test 2 is a fixture:** Trakt signed out or a separate test account (owed: Christian on the box), seeded data (a series with progress, a truncating title, an AIOStreams manifest; owed), settings snapshotted by `ready.sh --walk` and diffed by `done.sh`. No real-Trakt writes.
- **Remote session brief.** Hand-offs to a Mac session say only what is new; everything above is assumed read.
