## P2 (fix before merge)

1. **`Screens/MPVPlayerView.swift:2119-2129` (`cycleAspect`)**: every press of the Aspect pill writes the synced, profile-scoped resize mode, including the modes the user only passes through. Fit is the default and Stretch is fourth in the cycle, so the obvious use (a 4:3 file you want stretched) is Fill, Zoom, Stretch: the profile is left on **Zoom**, a value nobody picked. The next playback opens zoomed and cropped, and so does the phone (it shares the key). Even cycling back to the start writes three values. **Fix:** do not persist per press. Remember the synced value at session start; when the flash clears (the existing 2 s `aspectFlashWork`), write the settled mode if it is Fit/Fill/Zoom, and write nothing on Stretch (leave the session-start value). The UI leg's C28 restore keeps working; add a pure test for "settled value to persist" (fit→fill→zoom→stretch persists nothing, fit→fill persists fill).

2. **`Screens/Player/PlayerChapters.swift:91` + `Screens/MPVPlayerView.swift:2081-2098`, `:2666-2670`**: chapter starts are never checked against the duration. A file whose last chapter marker sits at (or after) the end (end markers on disc rips, a chapter list from a longer cut, a broken muxer) makes a Right click in chapter mode, or a Chapters tab row, issue `seek <duration> absolute`. The skip-chip code in this same file clamps for exactly this reason ("a target past EOF wedges mpv"); a seek to exactly the duration with `keep-open` also drops straight into the post-play cover. **Fix:** in `readChapters` (the duration is readable on `eventQueue` right there) drop chapters whose start is `>= duration - 1` when the duration is known, and in `seekToChapter` clamp to `durationSec - 0.5` as a backstop. Add a parse/resolver test with a chapter at the duration.

3. **`Screens/MPVPlayerView.swift:438`, `:1598`, `:1751`**: the harvest is on by default (Auto, 10 s) in every device build, and its one native call is the one that already aborts the app on the simulator (`MTLSimDriver` trap inside libplacebo's texture download). Whether the hardware Metal driver survives the same host-pointer import is unproven (B's own device-pass item 1). If it does not, every mpv playback crashes about 10 s in, on any build carrying this batch, and the only way out is a Developer row testers do not know about. **Fix:** a crash sentinel. Set a `UserDefaults` flag (`player.harvestInFlight`) on `eventQueue` before `screenshot-raw`, clear it after; at `viewDidLoad`, if the flag is still set (the process died mid-harvest), turn the harvest off for this device (`debug.harvestIntervalSec = -1` or a separate auto-off key), log it, and clear the flag. Cost is two defaults writes per harvest. Keep device-pass item 1 as the real proof.

## P3 (nice to have)

4. `Screens/MPVPlayerView.swift:1098`: the synced aspect is applied at `FILE_LOADED`, so a Fill/Zoom profile shows the first frames in Fit and then snaps. `playerSettings` is already read synchronously before `loadfile` (`resolvePreferredAudioLanguages`, `:815`), so set `panscan` / `video-aspect-override` / `video-zoom` as options in `setupMpv` before `:568` and keep the `FILE_LOADED` call for the published mode only.
5. `Screens/MPVPlayerView.swift:2102-2116`: `applyAspect`'s `eventQueue` block keeps the controller alive through `guard let self` and ends without a main hop, the C13 shape at a much smaller window (three writes plus a DEBUG read). If it is the last reference, `deinit` (timer invalidation, `mpv_terminate_destroy`) runs on `eventQueue`. End it with a strong `DispatchQueue.main.async` (the DEBUG log can move there), like `readChapters` does.
6. `Screens/Player/TransportPreview.swift:124`: with `releaseClick` on, `pressBegan` still sets `previewSec = origin + 10`, so every chapter-mode click draws a +10 s preview playhead and target label for the length of the press, then the seek lands on the chapter start somewhere else. Leave `previewSec` nil while `releaseClick && ticks == 0 && !moved`, and set it on the first `holdTick`.
7. `Screens/MPVPlayerView.swift:2666-2676`: `seekToChapter` neither clears a held commit preview nor re-arms the landing. A chapter click within ~1.5 s of a hold commit leaves the old target's preview playhead on the bar until the old `commitLandWork` fires. Call `armCommitLanding(generation:fallbackSec:)` with the chapter seek's generation (or clear `commitGeneration` and hand back the preview immediately).
8. `Screens/Player/HarvestScheduler.swift:45`: the seek-landed harvest ignores the slow backoff, so on a 4K file (where every harvest will take > 60 ms) each seek still triggers a heavy readback 1 s after landing, when the user is most likely to look at the picture. Skip the seek harvest once `backedOff`, or apply the tripled interval to it.
9. `Screens/MPVPlayerView.swift:1825` + `Screens/Player/MPVPlayerPanelAdapter.swift:137`: the Info tab's "Seek Previews" row shows `12 · 0.2 MB · RSS 110 MB` in Release builds. "RSS" is jargon on a user-facing tab (copy rule). Keep the RSS part under `#if DEBUG`, or show the row only in DEBUG.
10. `iosApp/NuvioTVUITests/PlayerTransportUITests.swift:345-350`: `elapsed` is taken before the `bar(app)` read that produces `livePos`, so the oracle is biased by one probe read (~1–1.5 s on the simulator) inside a 2.5 s tolerance. Read `livePos` first, then compute `elapsed`. The `<= 42` bound at `:338` has about 3 s of headroom over 35 s plus drift; widen to 45 or measure drift from the `[Scrub] begin base=` value instead of a pre-raise read.
11. `iosApp/NuvioTVUITests/PlayerTransportUITests.swift:596`: `testAspectStretchFillsOn43` skips unless `PLAYER_SMOKE_ASPECT_URL` is set, so C12's runtime proof that `video-aspect-override "16:9"` re-lays out the picture has not run. Run it once with a 4:3 file, or put "Stretch fills a 4:3 file" on the device pass explicitly.
12. `iosApp/NuvioTVUITests/PlayerTransportUITests.swift:438`: an unconditional `throw` inside `#if targetEnvironment(simulator)` leaves the rest of the test unreachable on simulator builds (a compiler warning). Use `try XCTSkipIf(true, …)` or wrap the remainder in `#else`.
13. `Screens/Player/PlayerChaptersTab.swift:17` and `MPVPlayerPanelAdapter.swift` `rebuildChapters`: rows reuse `group: .audio`, and the tab opens with focus on the first row, not the ticked current chapter; with many chapters the current one can be off screen. Add a chapters group (or a neutral one) and default focus to the current row. The chapter list is also read once at `FILE_LOADED`; if mpv ever revises `chapter-list` later (ordered chapters), the ticks go stale. Observing the property is cheap if it matters.
14. `Screens/MPVPlayerView.swift` `routeScrub` `.swipeUp`: raises the bar even while a panel is presented (no `presentedViewController` check), and a remote resize-mode change from the phone mid-playback is not reflected in the pill. Both harmless; note for the device pass.
