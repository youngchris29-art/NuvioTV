NuvioTV Search & Library Revamp

This board compares NuvioTV's Search, Discover and Library screens with the official Nuvio apps, the other Apple TV ports of Nuvio, VortX and Stremio, the big streaming apps (Apple TV app, Netflix, Prime Video, Disney+, HBO Max) and the media-centre apps (Infuse, Plex, Swiftfin). It sets out three directions for Search, three for Discover and four for Library, plus smaller pieces you can mix in, and ends with a recommendation and the questions only you can answer. Each direction has a rough mockup, what it fixes and what it costs.

Starting point

What NuvioTV does today

Read from SearchView.swift, SearchViewModel.swift, LibraryView.swift, LibraryViewModel.swift and the shared Kotlin repositories behind them.

Search

  • A plain text field in a glass pill. Selecting it opens the full-screen system keyboard, which covers the results, so results show only after you press Done. There is no live search.
  • One row per add-on search catalog, headed "Search • Movies". The add-on's name is never shown, so two add-ons with a catalog called "Search" give identical headers.
  • The same film appears once per add-on. There is no TMDB search and no people.
  • Up to 10 recent searches as chips, saved when you press Done, on this Apple TV only.
  • "No results." covers three different cases: no add-ons, every search source turned off, and a real empty search.

Discover

  • Sits under the empty search field. Hide Discover (UX-8) turns it off.
  • Three full chip rows (type, catalog, genre) above a paged poster grid, about six posters per row at Medium.
  • Add-on catalogs only. TMDB's discover filters exist, but only in the collection-folder editor.
  • Remembers the catalog per profile, but not the genre.

Library

  • One flat poster grid from the single Library Source picked in Settings (Nuvio, Trakt, Simkl or MDBList), with five sort chips. The first is labelled "Trakt Order" even for Simkl and MDBList.
  • No type filter, no lists, no watched or progress badges. The hold menu offers only Remove.
  • A Trakt, Simkl or MDBList library reads "Your library is empty" while it loads or after a failed sync, with no Retry.
  • A Saved / Debrid Cloud switch appears when a debrid provider is connected. Cloud is a plain settings-style list.
  • The grid doesn't page. BUG-69 was a login crash on a 10,000-title library.

Already built, never shown on tvOS

  • Library sections: the Trakt watchlist and personal lists; Simkl's Watching, Plan to Watch, On Hold, Completed and Dropped; MDBList lists.
  • A rows-or-grid layout mode (mobile's one-row-per-list Library), and a type filter.
  • A controller to create, rename and delete lists.
  • Loading, error and offline states for the library.
  • TMDB discover (used by collection folders) and the person page.

Most of the Library revamp is screen work. The data is already in shared code.

What testers have asked for

  • FEAT-37 (Steven): results while typing, as in official Nuvio. Still an open product call.
  • FEAT-10 and UX-8: pick which catalogs search uses, and hide Discover. Both shipped. Any rebuild keeps them.
  • BUG-47/48, UX-13: Back from See All and the grid's scroll position. Fixed; a rebuild must not bring them back.
  • FEAT-30 / FEAT-45: a sidebar or icon rail, which changes where Search and Library live.
Worth knowing before choosing

Four facts that shape every option

1 · The keyboard decides how live search can be

The system search field (.searchable) gives results under the keyboard as you type, Siri dictation, typing on an iPhone, and the viewer's own keyboard choice. Our HIG contract bans it because of a keyboard-bleed bug inside a TabView. bobsupra's NuvioTVOS and VortX both ship it on tvOS 26: they put it in its own NavigationStack and hide the tab bar while searching. Swiftfin and Plex also use the native field; Plex moved back to it after its custom field lost dictation and iPhone typing. A one-day spike would tell us whether the ban can go.

2 · Two keyboards, chosen in Apple TV Settings

Siri Remote owners get a single row across the top unless they pick Grid in Settings › General › Keyboard Layout. Grid is a 6-column block docked on the left with results beside it. A native search screen has to look right in both. bobsupra detects which one is showing and lays out around it. An Apple engineer said in 2022 that only Apple's own apps can make the grid keyboard slide away, so third-party results always share the width.

3 · Add-on search is noisy

Each add-on returns its own list, so one film can appear in four rows, and stream-only add-ons flood the results with single releases. Merging needs ranking. Orivio searches metadata add-ons first, caps each catalog at 40 results and each stream-only add-on at 8, and removes duplicates by id.

4 · The rail takes the left edge

With FEAT-45's rail set to Always Visible, 116 pt of every screen is reserved, and Left from the leftmost item enters the rail. Any design with its own left column (a grid keyboard, a Library list column) puts two columns side by side. Apple's own TV app pairs its floating sidebar with a category list in Library.

Patterns that keep coming up

  • Search is live, 0.3–0.5 s after the last letter, and the old results stay until new ones arrive.
  • Something to browse before typing: recent searches, then genre or category tiles, then trending.
  • Results grouped by type with the best match first, and people as round portraits.
  • Filters are pills that show their current value and open a menu or a sheet, with a count of active filters and a Clear.
  • A Library that shows all your lists at once: a left list (Apple TV app, Plex 2026) or one row per list (Nuvio mobile).
  • State on the card: watched tick, progress bar, new-episode badge.
  • Editing is press-and-hold, never a separate edit mode.

Anti-patterns

  • A custom search field that drops dictation and iPhone typing (Plex's 2025 preview).
  • Results that swap on every key press (official NuvioTV keeps them still on purpose).
  • Source switching at the top of a long page, so you scroll back up to change list (Plex 2025, reverted).
  • One filter at a time (Infuse), filters not remembered (Plex preview), focus lost after a filter change.
  • No letter jump in a 1,000-title library, or one that hides until you scroll fast.
  • Search flooded by stream-only add-ons (the problem Orivio's ranking fixes).
  • "Empty" shown while a synced library is still loading (NuvioTV today).

Search · a separate decision

How results are grouped

Any of the three directions can use any of these.

My pick, as the default

By type, merged

One row per type: Top result, Movies, Series, Collections, People. Duplicates are merged by id. Add-ons are ranked: metadata add-ons first, stream-only add-ons last and capped. The add-on that found a title shows on the stage (S3) or in the focused card's subtitle. What Orivio, VortX, Swiftfin, Infuse 8.5 and the Apple TV app do.

By add-on (today)

Keep it as a setting, "Group results by add-on", for people who search one add-on on purpose. Print the add-on's name in the header ("Cinemeta · Movies") so identical catalog names can be told apart. Stremio and official NuvioTV do this, and the Search Sources toggles (FEAT-10) still apply.

One grid with type chips

"All · Movies · Series · People — 24 results" above one poster grid (bobsupra, Prime Video). The densest option, and the natural fit for S2. People need their own chip, since portraits don't sit well in a poster grid.

Mix and match

Smaller pieces that work with any direction

Search and Discover

Typing without flicker

Keep the old results until the new ones arrive, and show one skeleton row only for add-ons that are still answering. Official NuvioTV does this on purpose after finding that swapping rows on every key "reads as flicker" on a remote.

Suggestions

A first chip with the typed text in quotes that submits it as is (bobsupra), then title completions from the add-ons' search catalogs (official NuvioTV ranks up to 8). The system's suggestion list only takes plain text, so chips are ours to draw.

People

TMDB person search, shown as round portraits, opening the person page we already have. Apple's guidelines and Infuse 8.5, Swiftfin and Netflix all do this.

Power-user chips

"Play a link or magnet" (typed or pasted from an iPhone) and "Debrid Cloud" next to the field, as VortX does. Stremio's field takes a pasted link too.

Recent searches saved on intent

Save a query when you open one of its results (VortX) or when it returns results (mobile), not on every Done. Remove one with a hold, clear all with a button. Optional sync per profile.

Specific empty states

"None of your add-ons can search", "All search sources are off" with a link to Settings, and "No results for ‘dnue’" with the query shown so typos are obvious (WWDC26).

Menu goes to the top first

In a long grid, Menu scrolls back to the first poster; a second Menu leaves (Orivio).

Filter sheet with auto-paging

VortX's sheet (include/exclude genres, decade, rating, runtime, upcoming), a count on the Filters pill, "38 shown · Clear", and more pages loaded until the grid has at least 18 titles.

Missing add-on hint

When a remembered catalog's add-on was removed, say so and offer the Add-ons tab instead of an empty grid (Stremio's Install button).

Library

Smart filters

Unwatched, In progress, Watched, Short (under 100 minutes). They combine, and each appears only when it would change the grid (VortX). The answer to Infuse's long-standing "one filter at a time" complaint.

Letter rail

For long lists in Title sort. Decide whether a letter jumps (Infuse, Plex) or filters (Swiftfin). Compress with dots when the alphabet doesn't fit, and keep it visible rather than only on fast scrolls.

State on the card

Watched tick, progress bar, "New episode", a finished-series mark. Mobile already shows watched badges; tvOS shows none.

Full hold menu

Mark watched, Move to list, Remove (with the mobile dissolve). Play/Pause on a poster plays without opening the page (Orivio).

Manage lists on the TV

Create, rename and delete Trakt and MDBList lists. The controller exists in shared code; official NuvioTV has the screens.

Remember the view

Sort, filters and type per list, per profile (Plex, Swiftfin). A clear-filters pill whenever any filter is on.

Pin a list to Home

Any list or filtered view becomes a Home row (Infuse Favorites, Channels). Fits Home's strip with no new layout.

Count line and source badge

"31 movies · 17 series" (Orivio) and TRAKT / SIMKL / MDBLIST (official NuvioTV), so people know what they're looking at.

Grid density

Poster or landscape cards and the column count per list, using Apple's 6/7/8-column sizes (Swiftfin).

Navigation chrome

How these screens meet the tab bar or the rail

With Tabs (today's default)

  • S1 hides the tab bar while the keyboard is up, as bobsupra does; Menu brings it back.
  • Apple pins the tab bar on split-view screens, so on L3 a bar that stays visible (BUG-66's symptom) is the expected behaviour.
  • A filter row directly under the tab bar (L1, D1) needs room for the focus lift, or the first pill clips.

With the rail (FEAT-45)

  • Left from the first pill, the keyboard's left column or the Library column enters the rail. That's the spike's "failed Left" rule, so nothing new is needed.
  • S2 and L3 add a second left column. Apple's tvOS 26 TV app has the same pair (floating sidebar plus the Library list), so it reads as normal, but Hide While Browsing suits these two screens better than Always Visible.
  • tvOS's search tab role (Tab(role: .search), tvOS 18+) is worth trying in the S1 spike, in case it changes where the system puts the field.
For you to overrule

Recommendation

Search: S1 · Native Search, with results grouped by type and add-ons ranked as in Orivio, People from TMDB, and per-add-on rows kept as a setting. It's the only direction that gives dictation, iPhone typing and the viewer's own keyboard for free, and Plex, which tried a custom field, went back to the native one. Start with a one-day spike: the system search field in its own NavigationStack inside our TabView, tried with both keyboard layouts, dictation, iPhone typing and the rail. If it fails, S2 is the fallback. Keep S3 for after Home's stage ships, as a second step for the results view.

Discover: D2 as the empty Search page, with D1's bar on every grid behind it. Recent searches, genre, decade and collection tiles, then a Trending row. D3's filter sheet and TMDB as a source can come later, without changing the layout.

Library: L3 · Split Library, built in two steps. First L1's grid with everything it lacks: the shared sections, badges, a full hold menu, smart filters, loading and error states, and paging. Then the list column. The Rows/Grid switch (L2) can be an option later, since shared code already has the layout mode. L4 is a separate feature, not part of this revamp.

  • Library step 1 (L1). Lowest risk, the biggest gaps, nearly all the data already in shared code.
  • The search-field spike. One day, and it decides S1 or S2.
  • Search and Discover together (S1 or S2, the grouping, D2 + D1), since they share the page.
  • Library step 2 (L3's column), once the rail settings are settled.
