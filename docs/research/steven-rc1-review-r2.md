## Checked and fine

- **Lookup consistency:** `downsample` stores a legacy decode under `storeBucket(1920, source)`, and `lookupBucket` computes the same value from the same recorded source, so a legacy caller always hits its own decode. A decode with no ImageIO size is stored at 1920 and looked up at 1920. `largest(in:atLeast:)` keeps the old largest-first order, so a sharpened hero is re-presented sharp.
- **Any-bucket callers left as they were, all intentionally:** `ArtworkColorStore` (`cachedImage`), `InlineTileArtLoader.inMemory` and the poster step (`cachedLargest`), the hero's poster stand-in, the `TitleLogoHeader`/`InlineTrailerTitleOverlay`/`SagaCard`/folder-logo first-frame seeds, and `cachedPlaceholder`. None of them commits a bitmap as hero-grade.
- **Stand-in is always the same picture:** `cached(backdropURL)` is family-only, and the stand-in is always below the legacy floor, since otherwise the legacy lookup would have hit. It is gated off for folders and collection heroes. It suppresses the poster fallback. Its URL is recorded, so `HeroSharpen.plan` upgrades it (TMDB → `original`; other hosts → the same file at form size). No CW-class card decodes a backdrop below the 768 bucket, so the stand-in is never a thumbnail.
- **No leaked polling:** `waitForRowsAtRest` exits on cancel or a generation bump. `cancelSharpen` runs on every identity change, on a nil target and on reschedule. The uncover task is generation-guarded. `expansionScrollTask` is single and is cancelled on supersede, on collapse and on disappear.
- **No per-frame state writes added:** `restSource` is a plain stored property. `wideItemId` lives in the reference box. `trailingFadeHeldFor` is written at most once per pass or collapse. The mask's `scrolled` is still a 0-crossing Bool transform.
- **Cover bookkeeping cannot go stale:** `coverRestoresFocus` is set at cover time, can only be raised while covered, and is reset at uncover.
- **Morph plan:** the inset is clamped to `viewportWidth − expandedWidth`, so the tile never starts before the leading edge (~820 pt clear of the leading ramp even at 711 pt wide). `endsInsideInset` covers both the clamped-at-end case and the unscrollable short-row case. Under the proxy fallback, scrolling still happens only on a real overflow.
- **Search, Detail, folders:** Search's `CatalogRowView` takes the inset and the hold from the same default environment as its mask. Detail and Episodes rows keep their titles as siblings outside the mask, and host no inline trailers. Folder heroes now wait (1.5 s budget) for a legacy decode instead of committing a tile-sized cover, and keep their `none → late` path.
- **Release:** nothing the fix adds outside `#if DEBUG` references a DEBUG-only symbol. `storeForTesting` is DEBUG-only and used only by tests, and `CatalogGridProbe`/`TrailerProbe` were already release-safe. The fix gate was Debug only, so rebuild Release before the cut.
- **Prefetch side effect (watch on device, not a defect):** the CW and Upcoming rows' first-focus hero prefetch (8 entries each) now re-decodes each backdrop at legacy size from the URLCache bytes, where `4665b300` skipped it on the card decode. That is about 30 MB in the small pool and 8 short `.normal` gate slots. The `[Artwork] pool` line on the device pass should show it.
- **Whole-batch fresh pass:** I re-read the Kotlin ranking and preparer hooks, `NextEpisodeAutoPlay`'s explicit `ranking:`, `NativePreparingLabel`, the `TitleLogoHeader` chain and the `PosterCard`/`LandscapeCard`/`SagaCard` decode sizes. I also re-read the `RowRestSource` additions, the `HeroArtResolver` present/commit/late paths, the edge-fade modifier and segment math, the Detail/Episodes fade placement, and `NuvioTVApp`'s migration and seed order. I found no P1 or P2 beyond round 1's list.
