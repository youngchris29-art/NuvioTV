## Checked and fine

- **Late replacement, identity and double adoption.** `standInStillUp` is re-read before every poll. `shouldAdoptLateBackdrop`, `presentedBackdropIsStandIn` and `adoptable` are all re-checked after the wait. The second `adoptLateBackdrop` call (fetch closure vs. resolve hand-off) cannot adopt twice: the first commit clears the flag, and `adoptable` refuses the same instance. A move away (A→B, or A→B→A with B uncommitted) is handled by the target/presented checks. The poster stand-in is never marked. `noteAdopted` runs before the commit, so the paint logs as `sharpen paint` and test62 sees `backdrop=late`. The Task exits on an identity change or a cleared flag; it holds `self` only for a rest wait, like the sharpen.
- **Rest-wait refactor.** `waitForRowsAtRest(hold:generation:)` behaves exactly as before: the same cancel and generation check before each poll. The stand-in wait does not depend on `sharpenGeneration`. `commitLateBackdrop` → `commit` → `scheduleSharpen` cancels a running sharpen by generation; the re-armed sharpen plans from the legacy bitmap and joins or hits the `original` already downloaded. In the rare order where the sharpen adopts first, the flag clears and the late Task exits.
- **In-flight mechanics.** The `inflight` lookup and insert are atomic on the main actor, with no `await` between them. The owner's `defer` clears only its own key. Joiners never hold a gate slot, so the gate cannot deadlock. An owner keyed by a `.legacy`, `.fullBleed` or `.pixels` request, or by a fill `.points` one, always covers a smaller joiner: fill keys understate the need, and legacy decodes `min(1920, source)`. Only fit owners overstate (#2).
- **`requestBucket` family aspect.** It relaxes only fit `.points` floors. Fill is provably unchanged: with a source, a fill need is at least `max(W, H)`, so `min` keeps the old floor. `.legacy` is untouched. Family members are one picture (the TMDB size segment, metahub poster sizes), so the aspect is right. Only logo call sites use fit. The new tests pin the hero, launch-head, first-play, fill and no-source cases.
- **Callers of the changed `ArtworkStore` APIs, all re-grepped:** `CachedImageLoader`, `TitleLogoHeader`, `SagaCard`, `CollectionsUI`, `InlineTileArtLoader`, `HeroArtResolver` (present, poster stand-in, sharpen), `HeroCommitCoordinator`, every `prefetch` site, `TitleLogoStore`. None depends on the old fit floor. `cachedLogo`/`fetchLogo` are protocol requirements with forwarding defaults, so `ArtworkStoreHeroFetcher` dispatches to its own versions and the `HeroCommitCoordinatorTests` stub still records logo fetches. The FolderDetailView header (legacy) misses a folder logo that only the hero's slot decode holds, and re-decodes it once. This is rare, because the collection row warms the legacy decode first.
- **First-play overlay.** It is hosted inside `StreamPickerView` and asks for the same request as the header there, so both share one `original` download. 600 × 120 covers the drawn 520 × 110 slot.
- **Trailing-fade hold.** The cards abort on the same disappear, so a card is never still wide when its row comes back. The clear is a single write, made only when a hold is set.
- **Listener re-arm.** The budget is one re-arm per focus visit, reset only in `reset()`. The re-arm is cancelled by `reset()` and `deinit`, captures `[weak self]`, and is guarded by generation, `.idle` and `activeKey == nil`. Its `startDwell` re-runs the rest gate. The hero host resets for every item through `syncTrailer`, and a carousel tick during the wait cancels it. Now that an idle card holds no `activeKey`, a stale resolve walk can no longer attach to it.
- **Strings.** The ten `detail.status.*` keys each carry an explicit `en` value plus fr/es/de/it/vi, all `translated`, with `extractionState: manual` and `en` equal to the `defaultValue`. All 27 new keys have five translations. A mechanical check found format specifiers matching their keys in every translation (`%@`/`%lld` count and order), and the debug probe strings are identical to their keys. `Preparing playback…` uses U+2026, like the `\u{2026}` literal. Every new UI literal in `284fd764..808e9ae4` now has a catalog entry. One minor point: `it` "Uscito" is masculine while the other Italian statuses are feminine. This is acceptable, because "Released" is a movie status.
- **Residuals, not new findings.** A joiner inherits the owner's admission and the 8 s `timeout` of a non-last candidate. The new cross-bucket pairs that hit this are rare: the hero's legacy backdrop joining a larger, still-queued, same-URL Detail or sharpen fetch needs an evicted legacy entry. The fetch doc's "nothing left to queue" is wrong for an owner that is still queued; that predates this commit. The stand-in replacement also fires for trivial gains: a `w780` source goes from 768 to 780 px, costing one cross-fade and a sharpen restart. That is harmless.
